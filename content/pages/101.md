  <h2 id="typed-errors">Typed errors — new in 0.6</h2>
  <p>
    FxDart 0.6 ports the <em>approach</em> of Kotlin's
    <a href="https://arrow-kt.io" rel="noopener">Arrow&nbsp;2.x</a> to Dart:
    a <code>Raise&lt;E&gt;</code> scope in which straight-line code can
    short-circuit with a <strong>typed</strong> error. There is no
    <code>TaskEither</code>, no <code>IO</code>, no wrapper tower to
    <code>flatMap</code> through — Dart's own <code>Future</code> and
    <code>throw</code> remain the effect system, and <code>Either</code>
    appears only at the boundary.
  </p>

  <h3>Short-circuit with <code>either</code></h3>
  <pre class="code"><code>Either&lt;String, int&gt; parsePort(String raw) => either((r) {
  final n = r.ensureNotNull(int.tryParse(raw), () => '"$raw" is not a number');
  r.ensure(n &gt; 0 &amp;&amp; n &lt; 65536, () => '$n is out of range');
  return n;
});

switch (parsePort('8080')) {
  case Right(:final value): print('listening on $value');
  case Left(:final value):  print('bad config: $value');
}</code></pre>
  <p>
    Inside the block, <code>r.bind(either)</code> unwraps another
    <code>Either</code>, <code>r.ensure</code>/<code>r.ensureNotNull</code>
    replace <code>require</code>-style checks (with null promotion), and
    <code>r.recover</code>/<code>r.withError</code> handle or translate
    errors. Async is the same shape with <code>eitherAsync</code>; the
    nullable-first twin is <code>nullable</code>, which returns
    <code>T?</code> instead of an <code>Either</code>.
  </p>

  <h3>Accumulate every failure, not just the first</h3>
  <pre class="code"><code>final user = either&lt;Nel&lt;String&gt;, User&gt;((r) => r.accumulate((acc) {
  final name = acc.accumulating((r) => validateName(r, input));
  final age  = acc.accumulating((r) => validateAge(r, input));
  return User(name.value, age.value); // all errors reported together
}));</code></pre>
  <p>
    <code>r.accumulate</code>, <code>r.zipOrAccumulate2..5</code>, and
    <code>r.mapOrAccumulate</code> run every branch, concatenate all errors
    into a <code>NonEmptyList</code> (<code>Nel</code>), and only fail at the
    end — Arrow's replacement for a separate <code>Validated</code> type.
  </p>

  <h3>Fused with pipelines</h3>
  <pre class="code"><code>// Validate 500 records, 8 at a time, and keep EVERY failure — in order.
final result = await fxStream(records)
    .mapOrAccumulate&lt;String, User&gt;((r, rec) async {
  final parsed = r.ensureNotNull(tryParse(rec), () => 'bad record: $rec');
  return await enrich(parsed);
}, concurrency: 8);</code></pre>
  <p>
    <code>rights()</code>, <code>lefts()</code>, <code>separated()</code>,
    <code>sequence()</code> and <code>mapOrAccumulate()</code> are eager
    terminals on <code>fx()</code>/async chains — fail-slow concurrent
    validation rides the same <code>concurrent(n)</code> back-channel as the
    rest of FxDart.
  </p>

  <div class="callout">
    <strong>Two rules.</strong> (1) Never return a <em>lazy</em> pipeline from
    a raise block — materialize with <code>toList()</code> or use the eager
    terminals above; a deferred raise fails loudly with
    <code>RaiseLeakedError</code>. (2) Never bare-<code>catch</code> inside a
    raise block — use <code>catching</code>/<code>catchingAsync</code>, which
    always let the short-circuit signal through (<code>on Exception</code> is
    already safe).
  </div>
