Typed errors — new in 0.6

FxDart 0.6 ports the approach of Kotlin's Arrow 2.x to Dart: a Raise<E> scope in which straight-line code can short-circuit with a typed error. There is no TaskEither, no IO, no wrapper tower to flatMap through — Dart's own Future and throw remain the effect system, and Either appears only at the boundary.

Short-circuit with either

Either<String, int> parsePort(String raw) => either((r) {
  final n = r.ensureNotNull(int.tryParse(raw), () => '"$raw" is not a number');
  r.ensure(n > 0 && n < 65536, () => '$n is out of range');
  return n;
});

switch (parsePort('8080')) {
  case Right(:final value): print('listening on $value');
  case Left(:final value):  print('bad config: $value');
}

Inside the block, r.bind(either) unwraps another Either, r.ensure/r.ensureNotNull replace require-style checks (with null promotion), and r.recover/r.withError handle or translate errors. Async is the same shape with eitherAsync; the nullable-first twin is nullable, which returns T? instead of an Either.

Accumulate every failure, not just the first

final user = either<Nel<String>, User>((r) => r.accumulate((acc) {
  final name = acc.accumulating((r) => validateName(r, input));
  final age  = acc.accumulating((r) => validateAge(r, input));
  return User(name.value, age.value); // all errors reported together
}));

r.accumulate, r.zipOrAccumulate2..5, and r.mapOrAccumulate run every branch, concatenate all errors into a NonEmptyList (Nel), and only fail at the end — Arrow's replacement for a separate Validated type.

Fused with pipelines

// Validate 500 records, 8 at a time, and keep EVERY failure — in order.
final result = await fxStream(records)
    .mapOrAccumulate<String, User>((r, rec) async {
  final parsed = r.ensureNotNull(tryParse(rec), () => 'bad record: $rec');
  return await enrich(parsed);
}, concurrency: 8);

rights(), lefts(), separated(), sequence() and mapOrAccumulate() are eager terminals on fx()/async chains — fail-slow concurrent validation rides the same concurrent(n) back-channel as the rest of FxDart.

Two rules. (1) Never return a lazy pipeline from a raise block — materialize with toList() or use the eager terminals above; a deferred raise fails loudly with RaiseLeakedError. (2) Never bare-catch inside a raise block — use catching/catchingAsync, which always let the short-circuit signal through (on Exception is already safe).
