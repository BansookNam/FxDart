Dart vs FxDart

같은 실전 과제를 두 번 풉니다: 왼쪽은 순수 Dart, 오른쪽은 FxDart입니다. 두 버전 모두 브라우저에서 바로 실행되며 정확히 같은 결과를 출력합니다 — 직접 비교하고 판단해 보세요.

목록을 보기 전에 한 가지는 정직하게 짚고 넘어가겠습니다: Dart의 내장 Iterable은 이미 지연 평가되며, 단순한 where/map 체인은 그 자체로 훌륭한 Dart 코드입니다. FxDart는 이런 코드를 이기려고 있는 게 아닙니다. FxDart가 더하는 것은 어휘 (groupBy, chunk, zip, scan, uniqBy, partition — 기본 Dart로는 직접 손으로 구현해야 하는 것들입니다), 조합(중첩 호출과 중간 변수 대신 타입이 있는 fx() 체인 하나로 표현하기), 그리고 무엇보다 동시성 제어입니다 — .concurrent(n)는 비동기 파이프라인을 한 번에 n개씩, 순서를 유지하며 실행합니다. 이는 순수 Dart로는 수작업 워커 풀로만 근접하게 흉내 낼 수 있는 부분입니다. 각 예제에는 판정 배지가 붙어 있고, 그중 일부는 네이티브 Dart로도 충분하다고 말합니다. 바로 그 점이 핵심입니다: 어떤 예제가 정말 FxDart가 낫다고 말할 때는, 그 말을 믿을 수 있습니다.

FxDart 승 — 이 경우는 명확히 더 낫습니다 · 우열 없음 — 둘 다 좋아서 취향껏 고르면 됩니다 · 네이티브로 충분 — 순수 Dart로도 잘 처리됩니다 · async — 비동기 파이프라인을 사용합니다

예제마다 두 가지 관점을 보여줍니다. 채워진 배지는 코드에 대한 판정 — 어느 쪽이 더 쓰고 읽기 좋은가입니다. 테두리만 있는 ⚡ 배지는 측정 결과 — 가장 큰 벤치마크 크기에서 AOT 컴파일로 실측한 실행 시간 승자이며, 전체 그래프는 각 페이지의 벤치마크 섹션에 있습니다.

다섯 개만 본다면, 이 예제들을 보세요: #1 가장 큰 지출 상위 3건 · #11 총지출 기준 상위 5개 판매자 · #23 상위 판매자를 동시에 보강하기 · #31 다중 통화 지출 리포트 · #53 두 스냅숏 사이의 가격 하락

    • toAsync

    • chunk
    • map
  6. 6 리더보드 순위 라벨 우열 없음 ⚡ 속도 동일 정렬된 리더보드에 1부터 n까지 번호를 매깁니다 — Dart 3의 indexed 레코드와 FxDart의 zipWithIndex + map을 비교합니다.
    • zipWithIndex
    • map
  7. 7 계좌 잔액 추이 FxDart 승 ⚡ 네이티브가 더 빠름 매 거래 후의 잔액 — 순수 Dart의 가변 누산 루프 대 FxDart의 scan + map.
    • scan
    • map
  8. 8 이번 달 식비 합계 FxDart 승 ⚡ 네이티브가 더 빠름 가계부 한 카테고리를 합산합니다 — 순수 Dart의 where/fold 체인과 FxDart의 filter + sumBy를 비교합니다.
    • filter
    • sumBy
  9. 9 첫 방문 순서로 보는 판매자 목록 FxDart 승 ⚡ 네이티브가 더 빠름 순서를 유지하는 중복 제거 — 순수 Dart의 seen-set 루프와 FxDart의 map + uniq를 비교합니다.
    • map
    • uniq
  10. 10 한계를 처음 넘긴 센서 측정값 네이티브로 충분 ⚡ 속도 동일 기준값을 넘는 첫 온도를 찾습니다 — 순수 Dart의 skipWhile + firstOrNull과 FxDart의 dropWhile + head를 비교합니다.
    • dropWhile
    • head

2부 · 함수 3개

네이티브 Dart에는 없는 어휘가 빛을 발하기 시작합니다: groupBy, uniqBy, partition, scan.

  1. 11 총지출 기준 상위 5개 판매자 FxDart 승 ⚡ FxDart가 더 빠름 가계부를 판매자별로 그룹화해 합계 순위를 매깁니다 — 순수 Dart의 groupListsBy + sortedBy와 FxDart의 groupedBy → sortByDesc → take 체인 하나를 비교합니다.
    • groupedBy
    • sortByDesc
    • take
  2. 12 모든 게시물의 태그를 정렬해 모으기 우열 없음 ⚡ FxDart가 더 빠름 게시물 태그를 하나의 정렬된 중복 없는 리스트로 평탄화합니다 — 순수 Dart의 expand + toSet + sort와 FxDart의 flatMap + uniq + sort를 비교합니다. 코드는 무승부, 시계는 1.5배 차이입니다.
    • flatMap
    • uniq
    • sort
  3. 13 환불과 청구, 둘 다 포맷팅 FxDart 승 ⚡ FxDart가 더 빠름 원장을 환불과 청구로 나누어 두 쪽 모두 출력합니다 — 순수 Dart의 where 두 번 대 FxDart의 partition 한 번을 비교합니다.
    • partition
    • map
    • join
  4. 14 정규화한 유효 이메일 상위 5개 네이티브로 충분 ⚡ 속도 동일 다듬고, 소문자로 바꾸고, 유효성을 검사한 뒤 다섯 개를 취합니다 — 순수 Dart의 map/where/take와 FxDart의 map + filter + take를 비교합니다. 이 경우 순수 Dart도 똑같이 깔끔합니다.
    • map
    • filter
    • take
  5. 15 두 개씩 프로필 가져오기 FxDart 승 async ⚡ 네이티브가 더 빠름 순서를 지키는 동시성 제한 — 순수 Dart로 직접 만든 워커 풀과 FxDart의 toAsync + map + concurrent를 비교합니다.
    • toAsync
    • map
    • concurrent
  6. 16 복리 이자 테이블 FxDart 승 ⚡ 네이티브가 더 빠름 연 5%의 연도별 잔액 테이블입니다 — 순수 Dart의 가변 누산 루프와 FxDart의 range + scan + map을 비교합니다.

    • scan
    • map
  7. 17 거래당 평균 지출이 가장 높은 카테고리 FxDart 승 ⚡ 속도 동일 지출을 그룹화해 거래당 가장 비싼 카테고리를 찾습니다 — 순수 Dart에서 collection의 groupBy + maxBy 중첩 호출과 하나의 FxDart 체인을 비교합니다.
    • groupBy
    • map
    • maxBy
  8. 18 특정 기간 안의 지출 우열 없음 ⚡ FxDart가 더 빠름 날짜순으로 정렬된 가계부의 한 구간을 합산합니다 — 순수 Dart의 skipWhile/takeWhile/fold와 FxDart의 dropWhile + takeWhile + sumBy를 비교합니다. 네이티브 쪽도 충분히 잘 버팁니다.
    • dropWhile
    • takeWhile
    • sumBy
  9. 19 센서와 측정값 짝짓고 이상치 찾기 FxDart 승 ⚡ 네이티브가 더 빠름 두 개의 병렬 리스트를 결합해 고온 측정값에 표시합니다 — 순수 Dart의 인덱스 루프(core에는 zip이 없음) 대 FxDart의 zip + filter + map.

  10. 20 최근 오류 메시지, 중복 제거 FxDart 승 ⚡ 네이티브가 더 빠름 최신순 로그에서 가장 최근의 서로 다른 오류 3개를 추출합니다 — 순수 Dart의 seen-Set 루프와 break 대 FxDart의 filter + uniqBy + take를 비교합니다.
    • filter
